# I’m-accessibility — seven-day v1 release-candidate sprint

**Dates:** 20–26 October 2026 · **Tracker:** [v1 release gates #3](https://github.com/Martin123132/im-accessibility/issues/3) · **Status:** scheduled, not shipped

## Outcome, not feature creep

Deliver a **repeatable Windows release candidate** for owner-controlled desktop viewing and LG remote input, with optional explicitly reviewed AI/Codex assistance. The planned first-release hardware target is **Windows 11 x64 with the LG OLED55CX6LA/webOS pathway**. The owner’s physically demonstrated machine is **Windows 10 Home 64-bit (build 19045)**; the Windows 11 + LG combination still requires independent clean-install and physical acceptance. Other Windows versions, TVs, assistive devices, streaming apps and games are experimental until separately validated.

The product must be usable by someone other than the original developer. A successful demo or green unit tests alone are not sufficient. This sprint is a time box, **not permission to skip release gates**. If an installation, safety or licence gate fails, release an accurately labelled technical preview rather than a general v1.

**Existing baseline (as checked 20 October):** repository public; PR #2 merged; 40 Windows CI tests, 38 passing, 0 failing and 2 needing live HLS. Original owner verified TV navigation and supervised Codex composer entry. The installed PC Bridge application is **not included** in this repository, so redistributability/integration must be resolved before claiming an all-in-one installation.

### Release scope

**In scope:** per-user installation/reversible setup; trusted-LAN desktop view; tested LG remote pointer/click/scroll; visible mouse permission expiry; owner Stop/Resume; stable reconnect; simple accessible dashboard; tests, privacy, source/binary provenance, licence notices, reproducible release artifact. Codex may be presented as a separate **optional manual review-and-send** companion.

**Out of scope for this week:** Apple Music, YouTube, Sky, broad voice navigation, Gears of War and other games, universal Smart TV compatibility, unattended Codex submission, public-internet remote desktop. These remain useful later edge-test tracks.

### Five gates before calling it product-grade

1. **Install/recover:** a clean install from the release artifact works without the original laptop path, and rollback/uninstall removes only our installed files, tasks and shortcuts.
2. **Operate:** on supported hardware a user can Start → view TV → enable 10-minute mouse lease → Pause → Stop/Resume without editing source or typing terminal commands.
3. **Safety:** no controls start armed, ambiguity and stale targets fail closed, Stop revokes fresh input, and uncertain Codex submissions never auto-replay.
4. **Reproduce:** Windows CI green; versioned source/artifact SHA-256; documented dependency and native binary provenance; no secrets, research files or personal screenshots in release.
5. **Independent evidence:** clean-machine/profile installation, physical LG test, readable/focusable UI, licence/security review and owner Go/No-Go recorded. An unverified gate remains open, not assumed passed.

## Important dependency decisions

- **PC Bridge:** the running Windows bridge is currently a separate installed product. Do not redistribute its executable, pairing keys or alpha components until ownership, licensing and a reproducible distributable build are established. If bundling is not authorised, v1's shipped core is the TV-control component; AI assistance remains an optional separately installed companion.
- **Installer:** if WiX, Inno Setup or NSIS is not available, begin with a per-user reproducible Windows setup/bundle and explicit rollback. An unsigned beta must be labelled as such; do not call it a signed final installer.
- **Network:** keep video and mouse control on a trusted LAN and restrict the native pointer broker to owner-armed bounded input.
- **Research:** no Codex research chat, live test, installed TV process or other ongoing project may be repurposed as a fixture. Disposable repositories and mock transports only, unless the owner expressly authorises a specific harmless live test.

## Every burst must leave durable work

1. Open the **next unchecked GitHub issue**, verify current branch/commit and isolate changes in a dedicated branch.
2. Do **one bounded change** with tests; save code, source hashes, reports, and any recoverable checkpoint on the Windows machine.
3. Open/update a PR with observed pass/fail results and blockers. Keep `main` green. No force pushes and no silent merge.
4. Update the issue checkboxes with the exact next action. Stop the work session when done; do not leave background tasks dependent on a ChatGPT conversation.
5. Only promote a tested branch to the release build after CI and safety checks.

**To resume in any chat:** “I’m-accessibility sprint: take the next unchecked issue in #4–#10, inspect current GitHub and PC Bridge status, complete one bounded burst, test and checkpoint it.” The GitHub issues and local source are the source of truth, not remembered chat text.

## Go / No-Go on 26 October

**GO:** all five gates have evidence, owner approves the supported-device release, and GitHub has a versioned reproducible artifact, hashes, quick-start/uninstall instructions, honest limitations, third-party notices and a recovery runbook.

**NO-GO:** if clean install, urgent Stop, licence rights, device operation, credentials, or rollback are unverified, publish only a clearly named **preview/candidate** and leave [release tracker #3](https://github.com/Martin123132/im-accessibility/issues/3) open. Preserve tested source and the full blockers list for work after the sprint.

*This sprint adds no automatic subscription dependencies, hosting charges or unattended machine access.*
