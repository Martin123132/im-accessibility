# Accessibility approach

I’m-accessibility is designed around **agency and flexibility**. A person should be able to control the PC themselves, ask for assistance or combine both during the same session.

## Principles

**Multiple control options.** The current LG interface supports pointer clicks and an arrow-control fallback. Voice control, switches and other input methods are design goals, not verified features.

**Readable at a distance.** Living-room controls should offer large targets, visible focus, clear state labels, readable text and sufficient contrast. Testing on one LG television is not evidence of universal accessibility.

**Human approval.** A draft should remain visibly different from a submitted action. The owner must be able to pause input and tell which conversation or application receives a command.

**Recoverable mistakes.** Wrong targets and unclear instructions should fail closed rather than guess. Recovery should be measured, not merely promised.

**Manual input is valuable.** Pressing Send yourself with a familiar remote can be the intended workflow, not something the product must take away.

## V1 accessibility validation

Before broader release, test the experience with people who have varied motor, visual, cognitive and fatigue-related access preferences. Record task success, required interventions, accidental actions, recovery time and usability of alternatives.

The v1 work includes keyboard navigation, focus order, non-colour-only status, labelled controls, adjustable sizing and screen-reader checks. **Formal WCAG conformance and assistive-technology compatibility have not yet been established.**

Feedback should describe the access barrier without requiring personal medical details or private desktop screenshots.
